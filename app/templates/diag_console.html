Diagnostic console — named entries, not a command line

Each button sends a catalog key to the engine. There is no field here for a command, a path or a shell fragment, and adding one would defeat the design. What a key may do is decided by the engine's own diag_catalog.py — which refuses an unknown key and is asserted there, per entry and by reading its syntax tree, to reach no order, no secret and no kill switch. Ops cannot widen that from this page.

Why this is safe to hand to a read-only session

An IP-whitelisted, futures-only, no-withdraw Binance key defeats a stolen key used from anywhere else. It does not apply to code running on the whitelisted host, and futures permission is not symbol-scoped — so the risk arbitrary execution here would carry is a position, not a withdrawal. That is the reason this is a fixed catalog: a leaked code costs disclosure and some disruption, never a trade.

Reads observe and return. Actions change something reversible and off the money path — flush a ledger, drop a rebuildable cache, re-seed one symbol. The kill switch, auto-execution mode, the position FSM and per-user settings are not here and must not be: they live on /control behind the owner's own login, which is the audit trail. Every run on this page is audited with the tier that ran it.
