Read-only access

{% call info("Exactly what a code can and cannot reach") %}

Short-lived codes that open the measurement and diagnostic pages — the feed, every lane, every export, the truth report — and never this control panel. Mint one here, hand it over, revoke it here.

A code cannot reach this control panel, the diag runner, the subscriber tables, the raw data volume or the /api/v1 token surface. A read-only session is refused on every method except GET, and on every route not explicitly classified as readable (app/guest_scope.py).

One deliberate exception, added 2026-08-19: a holder can run named entries from the engine's diagnostic console. Those are a fixed catalog, not commands — reads that only observe, plus a few reversible actions (flush a ledger, drop a rebuildable cache, re-seed one symbol). Nothing in that catalog can reach an order, a key, the kill switch, auto-execution mode or per-user settings, which is asserted in the engine per entry rather than promised. You can close the action half at any time by setting DIAG_ACTIONS_ENABLED=false engine-side, without revoking the code; every run is recorded in the audit log with the tier that ran it.

A read-only holder still sees real trading data — every signal, position and PnL figure on the pages above. This tier withholds the control plane and subscriber data, not the book.

Issued codes

{% call info("About revoking") %}

Revoking takes effect on the holder's next request — the session carries only the grant id and the grant is re-read every time, so there is no window in which a revoked code keeps working.

A non-zero Refused count is a holder that tried a surface it does not have — not necessarily an attack (a stale bookmark does it), and every refusal is named in the access log.
