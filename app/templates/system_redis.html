Why this page exists

On 2026-08-18 the owner was paged HIGH, repeatedly and with a recovery between each, reading: “Could not read snapshot:tickers idletime from the engine redis container … Probe said: no_output · rc=0 · exited 0 and printed nothing.” Every word after the fingerprint was true and the fingerprint was wrong.

docker exec exited 0. It cannot do that against a stopped container, and redis-cli exits non-zero when it cannot reach the server — so rc=0 is positive evidence redis answered. What it answered was nil, which redis-cli prints as nothing at all when stdout is not a terminal. The key was missing, not the container.

And a missing key is an engine fault. Every snapshot:* key carries a TTL of twice its write interval (snapshot:tickers: written every ~15s, TTL 60s), so an absent key means the SnapshotWriter missed several cycles. In isolated mode the api container reads these keys and nothing else — which is why the same stall that expired the key is what made the dashboard stop answering. Two symptoms, one event, and no surface joined them until this one.

So reachability and key presence are measured separately below and are never pooled again.

Every snapshot:* key ({{ redis.snapshot_key_count }})

TTL is the one to read. It counts down toward the moment the key evicts itself, so a low TTL on a key whose writer is healthy is normal (it is rewritten every cycle) and a TTL that is always low across the whole table is a writer running late. −1 means no TTL is set and −2 that the key vanished between the scan and the read — both are facts rather than errors, and pooling them into “no TTL” loses which one happened. Idle time is seconds since the key was last accessed, so a reader resets it: it grades traffic, not freshness.

Evicted keys and expired keys are not the same event and the difference decides the fix. Expired is a key reaching its own TTL — normal here, and what a stalled writer produces. Evicted is redis reclaiming memory under maxmemory, which would drop keys whose writer is perfectly healthy. A climbing eviction count with a healthy engine means the memory cap, not the writer.
